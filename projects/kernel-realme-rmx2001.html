The Challenge

The Realme 6 is unsupported hardware for running a conventional mobile Linux environment. This project investigates what it takes to adapt the device kernel, debug the boot path, and repurpose existing phone hardware as a low-cost Linux experimentation platform.

My Role

I worked across kernel configuration and builds, device boot and recovery workflows, partition-level troubleshooting, and Linux service deployment. Debugging relied on ADB and device logs rather than a standard desktop installation path.

What I Delivered

  • Device kernel work: A modified Realme 6 kernel repository aimed at Droidian compatibility.
  • Boot debugging: Investigation across recovery, partitions, kernel logs, and deployment failures.
  • Linux environment: A device-side environment for experimenting with services on reused hardware.
  • Remote access: Containerized services and secure connectivity through Docker, CasaOS, and Tailscale.

Key Decisions

Reuse hardware before buying more. The project treats an existing phone as a systems-learning platform, accepting device-specific constraints in exchange for a low-cost environment that exposes real kernel and deployment problems.

Debug from evidence. Boot logs, recovery behavior, partition state, and repeatable build output drive each iteration instead of relying on opaque trial and error.

Outcome

The repository documents an open, device-specific path toward running Droidian and Linux services on the Realme 6. More importantly, it demonstrates hands-on work below the application layer: kernels, boot flows, hardware constraints, and remote administration.

Tech Stack

  • Kernel: C, Linux kernel, Makefile
  • Mobile Linux: Droidian, ADB, recovery tooling
  • Services: Docker, CasaOS, Tailscale
